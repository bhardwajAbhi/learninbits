Part A

How this course works

One idea per chapter. Two working programs for each idea. Then a problem for you.

Code first Two examples in every chapter Your turn at the end

1Code first

Every idea in this course is a program that works. You do not only read about a prompt pattern. You build it, run it and see the result. Each chapter builds its program step by step, and explains every statement in the order that you type it.

2Two examples in every chapter

Each chapter builds the same idea two times, on two different problems:

  • Example 1 uses a Gemini model from Google.
  • Example 2 uses an open model through OpenRouter.

The two examples look at the idea from two sides. For instance, in the chapter on zero-shot prompts, one example sorts food reviews by feeling and the other example sorts security events by threat. When the same pattern works on two different problems, you understand the pattern, not only one example.

Real-life analogy

Think of a cooking class. In each lesson, the teacher cooks one recipe two times, with different ingredients. You see what stays the same and what changes. At the end of the lesson, you cook a new dish yourself.

Part B

Set up your workspace

Your project gets the same structure as the course repository on GitHub. Then one program tests all three model services.

uv and Python 3.11 Gemini, OpenRouter and Ollama Course repository

Here is what you will have when you finish:

Step 1Install uv

uv is a fast tool that manages Python projects. It installs the correct Python version, makes a private environment for your project and installs the libraries.

Linux and macOS:

curl -LsSf https://astral.sh/uv/install.sh | sh

Windows (PowerShell):

powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

Close the terminal and open it again. Then check that uv works:

uv --version

Step 2Create the project

uv init ai-engineering --python 3.11
cd ai-engineering
  • uv init ai-engineering makes a new folder ai-engineering with the start files of a project.
  • --python 3.11 sets Python 3.11 for this project. If Python 3.11 is not on your computer, uv downloads it for you.
  • cd ai-engineering moves you into the new folder.

uv made these files:

FileIts job
pyproject.tomlThe settings of the project: its name, the Python version and the libraries
.python-versionThe Python version of this project: 3.11
README.mdA short text about the project
.gitignoreThe files that Git must not save
main.pyA small start program. You do not need it, so delete it.

Now make the folder for your programs:

mkdir src

Step 3Add the libraries

uv add langchain-core langchain-google-genai langchain-openai langchain-openrouter langgraph python-dotenv langchain-ollama

uv add installs the libraries and writes them in pyproject.toml. It also makes uv.lock, with the exact version of each library, and .venv/, the private environment of the project.

LibraryIts job in this course
langchain-coreThe base parts: prompts, parsers and chains
langchain-google-genaiTalks to the Gemini models of Google
langchain-openrouterTalks to models from many companies through OpenRouter
langchain-openaiTalks to services that use the OpenAI format
langgraphBuilds agents as graphs, in later chapters
python-dotenvReads your secret keys from the .env file
langchain-ollamaTalks to Ollama on your own computer, for "Your turn"

Step 4Get your API keys

An API key is a secret password that lets your program use a model service. You need two keys:

  • Gemini: sign in at Google AI Studio and click Create API key.
  • OpenRouter: make an account at openrouter.ai and create a key on the Keys page.

Both services have free options to start with. Their limits change, so check their pages.

Step 5Store the keys safely

Create a file with the name .env.example. It shows which keys the project needs, with no values:

# OPEN ROUTER
OPENROUTER_API_KEY=

# GOOGLE GEMINI
GOOGLE_API_KEY=

Copy it to .env:

cp .env.example .env

Open .env and put your keys after the = signs. Do not use quotes and do not add spaces. Then open .gitignore and make sure that it contains this line. If it does not, add it:

.env
Security lens

.env holds your secret keys. The line in .gitignore tells Git to ignore this file. Thus, your keys never go to GitHub. .env.example has no secrets, so it can go to GitHub.

Step 6Install Ollama for local models

Ollama runs language models on your own computer. You need no API key, and no internet after the download. You use it in each "Your turn" section.

Linux:

curl -fsSL https://ollama.com/install.sh | sh

macOS and Windows: download the installer from ollama.com/download and run it.

Then download a small model and test it:

ollama pull llama3.2:3b
ollama run llama3.2:3b "Say hello in one word."
  • ollama pull downloads the model. It is about 2 GB.
  • ollama run sends one message to the model and prints the answer.

If your computer has little memory, use a smaller model, for example llama3.2:1b.

Step 7Check your folder

Your project must look like this:

ai-engineering/
├── .venv/            the private environment, made by uv
├── src/              your programs go here
├── .env              your secret keys, never share this file
├── .env.example      the list of keys, with no values
├── .gitignore
├── .python-version
├── pyproject.toml
├── README.md
└── uv.lock

Step 8Test everything with one program

Create the file src/00_check_setup.py and add this code:

"""
Title: Check the setup
uv run python src/00_check_setup.py
"""

from dotenv import load_dotenv
from langchain_core.output_parsers import StrOutputParser
from langchain_google_genai import ChatGoogleGenerativeAI
from langchain_openrouter import ChatOpenRouter
from langchain_ollama import ChatOllama


def check(name, llm):
    chain = llm | StrOutputParser()
    try:
        answer = chain.invoke("Reply with only the word OK.")
        print(f"{name:<12} works. Answer: {answer.strip()}")
    except Exception as error:
        print(f"{name:<12} does not work. Error: {error}")


def main():
    load_dotenv()
    check("Gemini", ChatGoogleGenerativeAI(model="gemini-3.1-flash-lite", temperature=0))
    check("OpenRouter", ChatOpenRouter(model="qwen/qwen-2.5-7b-instruct", temperature=0))
    check("Ollama", ChatOllama(model="llama3.2:3b", temperature=0))


if __name__ == "__main__":
    main()
  • load_dotenv() reads your keys from .env.
  • check(name, llm) sends one short message to one model and prints the result.
  • llm | StrOutputParser() makes a small chain that returns plain text. Chapter 2 explains chains in detail.
  • try and except catch an error. Thus, one broken service does not stop the check of the other services.
  • {name:<12} writes the name in a column of 12 characters, so the results line up.
  • main() checks the three services, one after the other.

Run it:

uv run python src/00_check_setup.py
Gemini       works. Answer: OK
OpenRouter   works. Answer: OK
Ollama       works. Answer: OK
Your output can be different

Your answers can be a little different, for example OK. with a period. Language models do not always answer the same way. That is normal.

If one line says "does not work," read the error:

The error containsWhat to do

model not found (Ollama)Run ollama pull llama3.2:3b
No module namedRun the uv add command of Step 3 again
Security lens
  • Your API keys are like passwords. A person with your key can use your account and your money. Keep keys only in .env. Never paste them into code, chats or screenshots.
  • If a key leaks, delete it at once on the website of the service, and create a new key.
  • Cloud models see your data. All text that you send to Gemini or OpenRouter goes to their servers. Do not send passwords or personal data in your tests. With Ollama, your data stays on your computer.

Check yourself

Why must .env be in .gitignore, but .env.example must not?

.env holds your real keys, so it must never go to GitHub. .env.example holds only the names of the keys, with no values. It tells other people which keys the project needs.

What does uv add change in your project?

It installs the libraries in .venv/, writes them in pyproject.toml and records the exact versions in uv.lock.

Which of the three model services works with no internet connection?

Ollama. It runs the model on your own computer. Gemini and OpenRouter run on servers on the internet.
