In one line

You send one question to a model with invoke(). You get back a message with the answer, the token count and the reason that the answer stopped.

What you will learn

  • How a Python program sends a question to a large language model (LLM)
  • What comes back from the model, and where the text of the answer is
  • What a token is, and why the token count matters
  • How to limit the length of an answer, and how to see that the limit cut it
  • Why the same code works with two different providers

Read chapter 0 first. It sets up the project, the libraries and the API keys that this chapter uses.

The idea

A large language model does not run inside your program. It runs on the servers of a provider, for example Google or a provider behind OpenRouter. Your program only sends a request over the internet and waits for the reply.

LangChain gives you a model object for this work. You create it one time, with the name of the model and some settings. Then you call invoke() with your question. The object sends the request, waits and gives you the reply as a message object.

The model reads and writes text in small pieces with the name tokens. A token is often a part of a word, a full short word or a punctuation mark. The provider counts the tokens of your question and of the answer. The count decides the price of the call and the time that it takes.

Real-life analogy

Think of a call to an expert help desk. You dial the number, ask one question and listen to the answer. The phone bill shows how long you spoke and how long the expert spoke. If you say "answer in five seconds," the expert stops in the middle of a sentence when the time ends.

The model object is your phone and invoke() is one call. The token count is the bill, and the maximum number of output tokens is the time limit.

Ask Gemini a question

Send one question to a Gemini model and print the answer, the token count and the finish reason.

Step 1Create the file

In your project folder, create the file src/01_basic_invoke_google.py and open it in your editor. You write the program in this file, one piece at a time.

Step 2Import what you need

Type these two lines at the top of the file.

from dotenv import load_dotenv
from langchain_google_genai import ChatGoogleGenerativeAI
  • from dotenv import load_dotenv takes the function load_dotenv from the python-dotenv library. This function reads your .env file, so your API key stays out of your code.
  • from langchain_google_genai import ChatGoogleGenerativeAI takes the class that talks to the Gemini models of Google. langchain_google_genai is the LangChain package for Google. "Chat" in the name tells you that the model works with messages.

Step 3Start the main function and load the keys

def main():
    load_dotenv()
  • def main(): makes a function with the name main. All the work of the program goes inside it.
  • load_dotenv() reads the .env file and puts each value into the environment of the program. After this line, the Gemini class finds GOOGLE_API_KEY by itself.

Step 4Create the model object

Inside main(), add these lines.

    # Initialize the model
    # For reproducible demos, keep temperature at 0 and bound the output length.
    llm = ChatGoogleGenerativeAI(
        model="gemini-3.1-flash-lite",
        temperature=0,
        max_output_tokens=128,
    )
  • The lines that start with # are comments. Python does not run them. They tell the reader why the settings have these values.
  • llm is the name of the variable. It is short for "large language model." You use this object each time that you talk to the model.
  • ChatGoogleGenerativeAI(...) creates the model object. It only stores the settings. It does not send anything yet.
  • model="gemini-3.1-flash-lite" selects the model. Flash Lite is a small and fast model in the Gemini family.
  • temperature=0 tells the model to select the most likely next token each time. The answers then change very little from run to run. Chapter 3 explains temperature.
  • max_output_tokens=128 sets the maximum length of the answer, in tokens. A short factual answer needs far fewer. The limit protects you from a very long and expensive answer.

Step 5Ask the question

    # Factual question
    response = llm.invoke("What is the capital of France?")
    print(f"Response: {response.content}")
  • llm.invoke("...") sends the question to the model and waits for the reply. This is the moment when the program uses the internet.
  • response holds the reply. It is an AIMessage object, not a plain string.
  • response.content is the part with the answer.
  • print(f"...") prints a line. The f before the string lets you put a value inside braces, here {response.content}.

Step 6Look at the token count

    # Inspect metadata (usage tokens)
    print(f"Usage Metadata: {response.usage_metadata}")

response.usage_metadata is a dictionary with the token count of the call. input_tokens counts your question, output_tokens counts the answer and total_tokens is the sum. Providers set the price per token, so this line shows the cost of the call.

Step 7Cut a long answer with a small limit

    # Example: Controlling output length
    print("\n--- Output Token Limit Example ---")
    short_model = ChatGoogleGenerativeAI(model="gemini-3.1-flash-lite", max_output_tokens=5)
    short_response = short_model.invoke(
        "Tell me a very long story about the history of the universe."
    )
    print(f"Short Response: {short_response.content}...")
    print(f"Finish Reason: {short_response.response_metadata.get('finish_reason')}")
  • "\n--- ... ---" prints a title. \n adds an empty line before it.
  • short_model is a second model object, with max_output_tokens=5. It can write only five tokens.
  • The question asks for a very long story on purpose. The model wants to write much more than five tokens.
  • The ... after {short_response.content} is only text in the print. It shows that the answer was cut.
  • response_metadata is a dictionary with extra details from the provider. .get('finish_reason') reads the reason that the answer stopped. get() returns None instead of an error if the key is missing.

Step 8Make the file start main()

At the bottom of the file, with no indent, add these lines.

if __name__ == "__main__":
    main()

Python sets __name__ to "__main__" only when you start this file directly. Then main() runs. When another file imports this file, main() does not start by itself.

Full code of Example 1src/01_basic_invoke_google.pyGitHub 
"""
Title: Basic LLM Invocation (Google Generative AI)
uv run python src/01_basic_invoke_google.py
"""

from dotenv import load_dotenv
from langchain_google_genai import ChatGoogleGenerativeAI


def main():
    load_dotenv()

    # Initialize the model
    # For reproducible demos, keep temperature at 0 and bound the output length.
    llm = ChatGoogleGenerativeAI(
        model="gemini-3.1-flash-lite",
        temperature=0,
        max_output_tokens=128,
    )

    # Factual question
    response = llm.invoke("What is the capital of France?")
    print(f"Response: {response.content}")

    # Inspect metadata (usage tokens)
    print(f"Usage Metadata: {response.usage_metadata}")

    # Example: Controlling output length
    print("\n--- Output Token Limit Example ---")
    short_model = ChatGoogleGenerativeAI(model="gemini-3.1-flash-lite", max_output_tokens=5)
    short_response = short_model.invoke(
        "Tell me a very long story about the history of the universe."
    )
    print(f"Short Response: {short_response.content}...")
    print(f"Finish Reason: {short_response.response_metadata.get('finish_reason')}")


if __name__ == "__main__":
    main()

Look closely

Here the content is a plain string, with no list and no signature. The same question used 36 input tokens with Qwen, but only 8 with Gemini. """
Title: Basic LLM Invocation (OpenRouter)
uv run python src/01_basic_invoke_openrouter.py
"""

from dotenv import load_dotenv
from langchain_openrouter import ChatOpenRouter


def main():
    load_dotenv()

    # Initialize the model
    # For reproducible demos, keep temperature at 0 and bound the output length.
    llm = ChatOpenRouter(
        model="qwen/qwen-2.5-7b-instruct",
        temperature=0,
        max_tokens=128,
    )

    # Factual question
    response = llm.invoke("What is the capital of France?")
    print(f"Response: {response.content}")

    # Inspect metadata (usage tokens)
    print(f"Usage Metadata: {response.usage_metadata}")

    # Example: Controlling output length
    print("\n--- Output Token Limit Example ---")
    short_model = ChatOpenRouter(model="qwen/qwen-2.5-7b-instruct", max_tokens=5)
    short_response = short_model.invoke(
        "Tell me a very long story about the history of the universe."
    )
    print(f"Short Response: {short_response.content}...")
    print(f"Finish Reason: {short_response.response_metadata.get('finish_reason')}")


if __name__ == "__main__":
    main()

When it works and when it does not

  • It works for one question with a fixed text. A direct invoke() is the simplest way to talk to a model.
  • It is less good when the question changes each time, for example with a name or a document inside it. Then you build the text with a prompt template. Chapter 2 shows how.
  • The model remembers nothing. Each invoke() is a new call. The model does not know your earlier questions. Later chapters show how to keep a conversation.
Security lens

Even this small program has three security points.

  • Protect the API key. Keep it in .env and add .env to .gitignore. A key in a public repository can be found and used quickly, and you pay for the calls.
  • Limit the length. Each token costs money. An attacker who can send long requests to your application can run up a large bill. A limit on output tokens is a first defense against this attack, which has the name "denial of wallet."
  • Your text leaves your computer. The question goes to the servers of the provider. Do not send passwords, keys or personal data of other people in a prompt. Send such data only if the terms of the provider allow it and you have the right to share it.

Check yourself

When does your program use the internet, at ChatGoogleGenerativeAI(...) or at invoke()?

At invoke(). Creating the model object only stores the settings. The request goes to the provider when you call invoke().

The finish reason is MAX_TOKENS. What does that tell you?

The answer is not complete. The limit on output tokens stopped the model before it finished. If you need the full answer, increase max_output_tokens or ask for a shorter answer.

Why did Example 1 print a list, and how do you print only the answer?

Gemini 3 models return the content as a list of blocks, with the text and a signature. response.text gives only the text, as one string, for every provider.

"""
Title: Basic LLM Invocation (Ollama)
uv run python src/01_basic_invoke_ollama.py
"""

from langchain_ollama import ChatOllama


def main():
    # A local model needs no API key, so this file does not call load_dotenv()
    llm = ChatOllama(
        model="llama3.2:3b",
        temperature=0,
        num_predict=128,
    )

    response = llm.invoke("In one sentence, what is a CVE in cybersecurity?")

    print("\n--- Output Token Limit Example ---")
    short_model = ChatOllama(model="llama3.2:3b", num_predict=5)
    short_response = short_model.invoke("Explain every type of malware in detail.")
    print(f"Short Response: {short_response.text}...")
    print(f"Done Reason: {short_response.response_metadata.get('done_reason')}")


if __name__ == "__main__":
    main()
