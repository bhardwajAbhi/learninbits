In one line

All the thinking patterns of Part III on one page, so that you can compare them and pick the right one for a task.

Part III shows different ways to make a model think before it answers. Each chapter teaches one pattern with two full examples and real output. This page puts those patterns side by side. Use it to compare them, to refresh your memory or to pick a pattern for a new task.

The page grows with the course. When a new chapter of Part III comes out, its pattern gets a place here too. For the code, the output and the details, open the chapter of each pattern.

All patterns at a glance

The table shows the cost of each pattern in model calls, the kind of task it suits and its main weak point.

PatternChapterModel callsGood forWatch out for
Chain of thought8OneOne correct way to the answer, for example a calculationWrong numbers inside neat steps
Tree of thought9OneA choice between real alternativesThe model judges its own paths
Graph of thought10OneA design or plan with connected partsToo much for simple questions
Step-back11TwoA specific case of a general ruleTwice the time, and errors travel to call 2
Least-to-most12TwoA long problem with many simple partsSmall models mix the two stages
Program of thought13One, plus code that runsAn exact number from a formulaCode from the model is untrusted

Most patterns need one call. Step-back and least-to-most need two, because the second call builds on the output of the first. Program of thought needs one call, but your program also runs the code from the model.

Pick a pattern for your task

The right pattern depends on the shape of the task, not on its topic. A security question can need any of these patterns. Look at what the task asks for, then follow the line that fits it best.

When a task fits no line, start with chain of thought. It is the simplest pattern, and its steps show you where the model goes wrong. That tells you which other pattern to try next.

Each pattern in short

Each block below gives the idea, the key prompt line from the chapter code, the kind of reply and the main risk. The prompt lines are copied exactly from the repository.

Chain of thought, chapter 8

The model writes its steps before the answer. A task with several steps then becomes more reliable and easy to check.

Key prompt line

Solve the following cybersecurity problem using clear and verifiable calculation steps.
  • The reply. Numbered steps with the formula of each step, then the final answer.
  • Watch out. The steps can be wrong too. A correct formula can come with a wrong result, so check important numbers with code.

Tree of thought, chapter 9

The model explores several paths, compares them and only then recommends one.

Key prompt lines

Generate 3 DIFFERENT response strategies.
Evaluate which path carries the least risk and why.
  • The reply. Path A, Path B and Path C, each with its reasoning and likely outcome, then a comparison and one recommendation.
  • Watch out. The model writes and judges its own paths in one pass. Use the paths as input for a human decision, not as an automatic action.

Open chapter 9

Graph of thought, chapter 10

The model splits a problem into connected nodes, solves them in the order of their dependencies and joins the results into one answer.

Key prompt lines

Identify 4-5 key sub-questions or concepts (nodes) needed to solve this problem.
Solve the nodes in dependency order (solve dependencies first).
  • The reply. A NODE, DEPENDS ON and SOLUTION block for each node, then one combined answer.
  • Watch out. A structured answer looks like expert work. Check it for invented numbers and for important nodes that are missing.

Step-back, chapter 11

The model first names the general principles behind a question, then uses those principles to answer the specific case.

Key prompt lines

List 2-3 fundamental principles, then briefly explain each.
Use the following principles to answer the specific question.
  • The reply. Call 1 gives two or three principles. Call 2 applies them step by step and gives the answer.
  • Watch out. Two calls take twice the time. A wrong principle or an injection in call 1 travels into call 2, so treat the output of call 1 as untrusted.

Open chapter 11

Least-to-most, chapter 12

The model splits a hard problem into small subproblems, from the simplest to the hardest, and solves them in that order.

Key prompt lines

Break down this complex problem into smaller subproblems.
Solve each subproblem in order, using solutions from previous subproblems when needed.
  • The reply. Call 1 gives a numbered list of subproblems. Call 2 solves them in order and combines the results into one answer.
  • Watch out. Small models often solve the whole problem in the planning call. The arithmetic can still be wrong, so check exact numbers with code.

Open chapter 12

Program of thought, chapter 13

The model writes a small Python program for a problem, and Python computes the exact answer.

Key prompt lines

Solve this problem by writing Python code.
Put your code in a ```python``` block.
  • The reply. A short explanation and one Python code block. Your program extracts the code, runs it and reads the result.
  • Watch out. Code from a model is untrusted input. Never run it with exec() on problems from users. The formula itself can also be wrong.

Open chapter 13

Patterns work together

The patterns are not rivals. A real program often combines two of them, and the chapters already show this.

  • Step-back with chain of thought. The second prompt of chapter 11 says "Apply the principles step-by-step". The model thinks in steps on top of the principles.
  • Least-to-most with program of thought. Chapter 12 shows a model that plans a calculation well and still computes it wrong. Chapter 13 fixes exactly that, because Python does the arithmetic.
