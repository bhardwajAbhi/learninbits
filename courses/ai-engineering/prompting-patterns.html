In one line

All the prompting patterns of this course on one page, so that you can compare them and pick the right one for a task.

The prompting chapters of this course show different ways to get a better answer from a model. The first group, Talk to the model well, sets the role, the task, the examples and the shape of the answer. The second group, Make the model think, makes the model reason before it answers. This page puts all those patterns side by side.

Use it to compare the patterns, to refresh your memory or to pick a pattern for a new task.

Most patterns need one call. Step-back and least-to-most need two, because the second call builds on the output of the first. Program of thought needs one call, but your program also runs the code from the model. Self-consistency needs one call for each sample.

Pick a pattern for your task

The right pattern depends on the shape of the task, not on its topic. A security question can need any of these patterns. Look at what the task asks for, then follow the line that fits it best.

When a task fits no line, start with zero-shot. If the answer has the wrong label or the wrong format, add examples or a role. If the task has several steps, move on to chain of thought.

Each pattern in short

Each block below gives the idea, the key prompt lines from the chapter code, the kind of reply and the main risk. The prompt lines are copied exactly from the repository.

Talk to the model well

These patterns set the role, the task, the examples and the shape of the answer.

System message, chapter 4

A system message tells the model who it is and how to answer. The same question then gets a very different answer for each role.

Key prompt lines

You are an experienced cybersecurity analyst.
Keep the explanation concise.
  • The reply. An answer in the style, depth and format of the role, for example technical terms for an analyst or a simple story for a learner.
  • Watch out. "You are an expert" changes the style, not the knowledge of the model. Check the facts. Keep the system message short and test each rule in it.

Zero-shot, chapter 5

Zero-shot means that you ask the model to do a task with no examples. You give it only the instruction.

Key prompt lines

Classify the sentiment of the following Indian food review as
POSITIVE, NEGATIVE, or NEUTRAL.
Respond with only the classification label.
  • The reply. One label and nothing else, because the prompt ends with a cue such as Sentiment: and an output rule.
  • Watch out. The input text can come from an attacker. A sentence such as "Ignore the rules above" inside the input is prompt injection.

Few-shot, chapter 6

A few-shot prompt shows the model some solved examples first, so it learns your labels and your rules from them.

Key prompt lines

("human", """The model provided the title and DOI of a research paper, but the paper does not exist."""),
("ai", "HALLUCINATION"),
  • The reply. One of your own labels, in the same format as the examples.
  • Watch out. Select the examples with care. Cover every label and the hard cases. The examples do not teach reasoning for tasks with several steps.

Open chapter 6

Structured output, chapter 7

Structured output makes the model answer in a fixed shape, such as JSON with named fields, so your code can use the answer directly.

Key prompt lines

Report only information stated or reasonably evident in the policy.
{format_instructions}
  • The reply. One JSON object with the named fields. A parser turns it into data that your code reads.
  • Watch out. Structure does not mean truth. Validate the values, because a wrong value can travel into a database or a report.

Make the model think

These patterns make the model reason before it answers.

Chain of thought, chapter 8

A chain-of-thought prompt asks the model to write its steps before the answer. A task with several steps then becomes more reliable and easy to check.

Key prompt line

Solve the following cybersecurity problem using clear and verifiable calculation steps.
  • The reply. Numbered steps with the formula of each step, then the final answer.
  • Watch out. The steps can be wrong too. A correct formula can come with a wrong result, so check important numbers with code.

Tree of thought, chapter 9

A tree-of-thought prompt makes the model explore several paths, compare them and only then recommend one.

Key prompt lines

Generate 3 DIFFERENT response strategies.
Evaluate which path carries the least risk and why.
  • The reply. Path A, Path B and Path C, each with its reasoning and likely outcome, then a comparison and one recommendation.
  • Watch out. The model writes and judges its own paths in one pass. Use the paths as input for a human decision, not as an automatic action.

Open chapter 9

Graph of thought, chapter 10

A graph-of-thought prompt splits a problem into connected nodes, solves them in the order of their dependencies and joins the results into one answer.

Key prompt lines

Identify 4-5 key sub-questions or concepts (nodes) needed to solve this problem.
Solve the nodes in dependency order (solve dependencies first).
  • The reply. A NODE, DEPENDS ON and SOLUTION block for each node, then one combined answer.
  • Watch out. A structured answer looks like expert work. Check it for invented numbers and for important nodes that are missing.

Step-back, chapter 11

Step-back prompting first asks the model for the general principles behind a question, then uses those principles to answer the specific case.

Key prompt lines

List 2-3 fundamental principles, then briefly explain each.
Use the following principles to answer the specific question.
  • The reply. Call 1 gives two or three principles. Call 2 applies them step by step and gives the answer.
  • Watch out. Two calls take twice the time. A wrong principle or an injection in call 1 travels into call 2, so treat the output of call 1 as untrusted.

Least-to-most, chapter 12

Least-to-most prompting splits a hard problem into small subproblems, from the simplest to the hardest, and solves them in that order.

Key prompt lines

Break down this complex problem into smaller subproblems.
Solve each subproblem in order, using solutions from previous subproblems when needed.
  • The reply. Call 1 gives a numbered list of subproblems. Call 2 solves them in order and combines the results into one answer.
  • Watch out. Small models often solve the whole problem in the planning call. The arithmetic can still be wrong, so check exact numbers with code.

Program of thought, chapter 13

Program of thought lets the model write a small program for a problem, and the computer runs that program to get the exact answer.

Key prompt lines

Solve this problem by writing Python code.
Put your code in a ```python``` block.
  • The reply. A short explanation and one code block. Your program extracts the code, runs it and reads the result.
  • Watch out. Code from a model is untrusted input. Never run it directly on problems from users. The formula itself can also be wrong.

Self-consistency, chapter 14

Self-consistency lets the model work through a problem several times and takes a vote on the final answers. The most common answer wins.

Key prompt lines

Solve this problem step by step.
[After reasoning, state your final answer on its own line as:
FINAL ANSWER: <answer>]
  • The reply. Several replies, each with its reasoning and one FINAL ANSWER line. Your program counts the answers and keeps the most common one with its share of the votes.
  • Watch out. Each sample is a full call, so time and cost grow with the number of samples. Runs that agree can still all be wrong, and a vote cannot count long written answers.

Patterns work together

The patterns are not rivals. A real program often combines two of them, and the chapters already show this.

  • System message with few-shot. In chapter 6, the system message gives the role, the allowed labels and the output rule. The solved examples follow as messages.
  • Step-back with chain of thought. The second prompt of chapter 11 says "Apply the principles step-by-step". The model thinks in steps on top of the principles.
  • Least-to-most with program of thought. Chapter 12 shows a model that plans a calculation well and still computes it wrong. Chapter 13 fixes exactly that, because the computer does the arithmetic.
  • Chain of thought with self-consistency. Chapter 14 runs the step-by-step prompt of chapter 8 several times and lets the answers vote.
